# 调研与选型

只取本次有关的字段，复用已有信息，不要求逐项填满。区分用户已定条件、需要查证的事实与尚未决定的偏好。

## 补漏字段

- 需求：要支持什么实际任务？比较结论将帮助用户决定什么？
- 约束：用户已给出的环境、预算、数据、接入或交付限制；不自行补默认值。
- 候选：保留用户指定对象；需要寻找替代方案时，按需求筛选，不为凑数追加候选。
- 证据：优先官方文档、仓库和可核实材料，记录来源与核查日期；涉及开源采用时核对许可证及适用范围。
- 比较：使用与本次需求有关的维度；区分文档宣称、实际测试和未知项，不强造评分与权重。
- 结论：说明适用条件、主要权衡及证据不足之处；缺少关键条件时给条件式结论。

## 整理方式

按“需求与约束 → 候选证据 → 同维度比较 → 结论与取舍”组织请求。比较表只在有助于判断时使用；调研不自动授予安装、采购或接入权限。

## 示例

原始想法：比较 A 和 B 哪个适合给现有项目做全文搜索，只调研，不安装。

增强结果：调研 A 与 B 对现有项目全文搜索需求的适配情况，只调研、不安装。先复用项目中能确认的需求和约束，核查两者官方资料及适用许可证，附来源与核查日期；按相关维度比较接入条件与主要取舍，区分资料结论和实测结果。给出有依据的建议；关键条件仍未知时说明各自适用条件。
