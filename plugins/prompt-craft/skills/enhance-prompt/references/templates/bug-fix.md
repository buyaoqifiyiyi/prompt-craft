# 故障排查与修复

只取本次有关的字段，复用已有信息，不要求逐项填满。缺少的运行证据留给执行者调查；无法自行确定的重要用户选择才澄清。

## 补漏字段

- 现象：哪个操作、输入或场景出了问题？保留用户描述的影响。
- 预期：用户希望出现什么结果？与现有约定或正常行为如何对应？
- 复现：已有步骤、发生条件、频率及正常对照；未知处不编造。
- 证据：相关报错、日志、截图、输入与代码位置；区分事实、假设和待验证原因。
- 范围：本次是只排查、给建议还是修复？保留允许修改和明确排除的范围。
- 验证：复现原问题，按影响检查相关正常路径；无法复现或运行时报告证据缺口。

## 整理方式

按“现象与预期 → 复现及证据 → 定位原因 → 授权内处理 → 相关回归”组织请求。局部故障不扩成全仓审查，不预定尚无证据的根因或技术方案。

## 示例

原始想法：搜索框输入中文后按回车没结果，点搜索按钮正常，帮我修复。

增强结果：排查并修复中文搜索按回车无结果、点击搜索按钮正常的问题。先阅读相关代码，对比两种操作的行为并尽可能复现，用证据定位原因；修改覆盖该问题及必要关联部分。验证中文回车搜索和现有按钮搜索，并说明原因、改动与实际验证结果。
