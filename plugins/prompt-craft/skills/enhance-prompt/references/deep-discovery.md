# 深度质询

仅在用户主动要求深入 grill、全面梳理或压力测试时读取。用户只是想润色表达时，不进入此流程。

把想法视为有依赖关系的决策树。例如：目标用户决定使用情境，使用情境决定首版范围，首版范围再决定交付与验收。每轮只问前提已明确且会改变结果的事项；不罗列所有可能问题。

1. 从已有想法提取目标、约束、依赖和潜在矛盾；可从当前材料直接取得的事实先自行查清。
2. 选择当前最重要的 1–3 个决策，编号提问，并给出可接受或修正的推荐答案。建议不是已经确认的决定。
3. 根据回答更新已确认事项与待定事项，沿重要依赖继续。一次回答已覆盖的问题不再问。
4. 用户说“继续”时推进重要未决项；说“生成”“先这样”或收窄范围时，按已有信息生成最终提示词。
5. 当执行目标、必要输入、关键范围和完成条件已明确，且余下事项可以合理默认或交给执行者调查时，交付提示词。不得为遍历每个枝节拖延产出。

识别问题的用途：这个答案会改变谁使用、交付什么、能做什么或如何判定完成吗？如果只影响微小可逆细节，就提出建议并继续。

发现薄弱假设时，说明与目标的关系，给出可选方向；不把质询扩成用户未请求的产品策略、重构或风险审计。

访谈阶段只产生对话中的需求整理和最终提示词。完成后按入口保留的交接模式处理：PROMPT_ONLY 交付提示词即结束；AUTO_CONTINUE 回到当前助手继续执行已确认的原任务。访谈本身不自动建立会话文件、知识库或外部记录；执行阶段仅按原任务范围创建所需产物。

本模块借鉴 Matt Pocock 的决策树与依赖顺序方法，并独立改编为有结束条件的提示词生成流程。来源与许可见插件根目录 `SOURCES.md` 和 `LICENSES/`。
